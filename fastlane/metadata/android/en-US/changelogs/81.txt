# SpaceKai v0.3.3

> Validation release for the in-app update manager — its purpose is to be
> detected and installed by a running v0.3.2 through Settings → Updates, to
> prove the full on-device update path.

## What's changed

Seventeen commits since v0.3.2, mostly hardening and finishing the pieces the
Update Manager and compact settings rely on.

### Update Manager (P0)
- The APK is now **package-verified before install**: the downloaded file is
  parsed (`getPackageArchiveInfo`) and must report exactly
  `com.maxrave.simpmusic`. A mismatched or unparsable APK is deleted and
  refused with an explicit error — the Android installer is never reached with
  a wrong package.
- Update screen honesty: before the first check the row now shows
  "dernière : —" instead of the broken "v—" label; installed version and latest
  are still read live (build version + GitHub `/releases/latest`), never a
  constant.
- `SPACEKAI_VERSION` is derived from the build version instead of the
  hardcoded release constant, so the "Installed" row can never drift from the
  real build again.
- The semantic update trigger (no false "update available" on re-cut tags)
  landed in v0.3.2 on the same base and is unchanged.

### Upstream tracking (P0)
- `upstream.lock` is now the source of truth for the integrated SimpMusic
  base; `scripts/update-upstream.sh` reads/writes it, and the app's "Base
  intégrée" row is built from it (BuildKonfig) instead of a constant.
- Docs: upstream 2.0.0 audit + feature matrix, and the E2E update-manager
  protocol (`docs/E2E-UPDATE-MANAGER.md`).

### Settings & UI
- Dynamic Color: the last forced-black surfaces on regular-theme screens (the
  multi-select bars on Recently Songs and Dynamic Playlist) now follow the
  Material You palette; all remaining blacks are by design (immersive screens,
  scrims, overlays).
- Settings are fully collapsible: every section (including Interface, SpaceKai
  and the Last.fm block under Discord) is closed by default, single-open, and
  a closed section does not compose its body.
- Crossfade duration is now a live 1-30s visual slider (0 = Auto) with
  haptics on release (earlier wiring on this base).
- Haptics: centralized `HapticManager` with ON/OFF and Low/Medium/Strong
  intensity, wired to tab selection (flat bar, rail, liquid glass), SpaceKai
  toggles, the crossfade slider and the player actions.
- Navigation: exclusive style choice (liquid glass / translucent /
  minimalist), icons-only minimalist mode, and configurable order/hide with
  persistence.

### CI
- Fail-fast: `android.yml` now runs the JVM compile + the repo's gate suite
  before the heavy Android build, so a broken push fails in ~1 minute instead
  of burning a ~20-minute build.

### Known / not finished (honest)
- The full **on-device update path** (download → SHA-256 → package check →
  Android installer) is only compile/test/gate/CI-verified — it has **not**
  been run on a physical phone yet. This release exists precisely so that test
  can happen: install v0.3.2, open Settings → Updates, and let v0.3.3 install
  itself over it.
- Several SpaceKai feature flags remain PARTIALLY / NOT IMPLEMENTED — the
  feature-audit block below is the complete list; nothing here claims them
  done.
